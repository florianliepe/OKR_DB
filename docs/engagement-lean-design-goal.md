# Zielmode instruction — engagement and lean experience

## Objective

Make the OKR Cockpit a useful weekly working rhythm: direct each person toward the smallest meaningful next action, help teams improve together, and reduce interface weight without rewarding application usage for its own sake.

## Engagement rules

- Reward current evidence, resolved risks, focused OKR design, completed context, reflection, and shared learning.
- Never reward logins, clicks, session duration, raw update volume, permanently green confidence, or target inflation.
- Keep individual Momentum and achievements private. Make only normalized team challenges and team learning visible.
- Enable constructive team challenges automatically for every active cycle.
- Deliver reminders, summaries, celebrations, and preferences only inside the application.
- Explain each recommendation, milestone, score, and challenge with a concrete underlying signal.
- Treat celebrations as brief acknowledgement, not interruption.
- Derive privacy-safe analytics from outcome activity and aggregate them before display.

## Lean experience rules

- Make Weekly Focus the shortest path to work requiring attention.
- Keep Overview decision-oriented; replace decorative charts with deltas, exceptions, and concise summaries.
- Use one unified detail drawer for Objective/KR context, evidence, dependencies, activity, and discussion.
- Let Ctrl/Cmd+K find destinations, Objectives, Key Results, and common actions.
- Default Objective cards to title, owner, progress, health, and next action; progressively disclose the rest.
- Consolidate filtering into saved task views and a compact filter surface.
- Keep one primary action per screen and move secondary actions into overflow menus.
- Every empty state explains the purpose and offers one appropriate next action.
- Meet keyboard, focus, reduced-motion, semantic landmark, contrast, and screen-reader requirements.

## Delivery sequence

1. Engagement domain: weekly focus, team challenges, milestones, learning feed, notifications, retrospective recognition, and aggregate analytics.
2. Interaction layer: Weekly Focus view, notification center, unified detail drawer, item command search, comments, and in-app preferences.
3. Lean visual layer: decision summaries, simplified cards, saved views, consolidated filters, reduced actions, and improved empty states.
4. Quality layer: automated domain tests, local desktop/responsive browser QA, CI, deployment, and production verification.

## Acceptance criteria

1. Each signed-in user receives a private, evidence-based next-action queue and meaningful streak guidance.
2. Every active cycle exposes automatic, transparent team challenges and cycle milestones.
3. The application provides a learning feed, subtle celebrations, guided retrospectives, in-app summaries, and notification preferences.
4. Owners can inspect privacy-safe aggregate engagement health without individual surveillance metrics.
5. Objectives and Key Results are searchable from the command palette and open in a unified contextual drawer.
6. Overview, saved views, filters, cards, actions, and empty states use the lean interaction rules above.
7. Individual achievements never appear in a public leaderboard.
8. Automated tests, local browser QA, CI, Pages deployment, and authenticated production verification pass.
